# Lively Class——AI教育Agent 产品说明与使用指南

Lively Class——AI教育Agent · 应用版本 0.1.0 · 文档更新日期 2026-10-21

本文依据当前代码说明可用功能。章节结构参考 `XZB2.pdf`（2026-10-02）；其原型页面和建议字段属于设计参考，不代表本项目已实现。当前功能与规划的对照见《实现状态与路线图》。历史首版材料独立归档。

四项核心能力与当前入口见[四项功能核对](四项功能核对.md)。

## 1. 引言

### 1.1 目的与范围

Lively Class——AI教育Agent 面向有使用权的教材、讲义和知识型 PDF，将资料整理成一节中文教学课，输出课程目标、逐段讲稿、来源摘录、SVG 图示、教学视频和 PPTX。目标用户包括教师、自主学习者及教学内容制作人员。

当前为本机运行的单用户应用。每份 PDF 对应一个生成任务和一节课；没有账户、机构资源库或多课程项目管理。长资料不受固定页数和目标时长限制，但模型调用、渲染时间与文件大小会随内容增长。

### 1.2 术语

| 术语 | 本项目中的含义 |
| --- | --- |
| 任务 / Job | 一个上传 PDF 的处理实例，由 32 位任务编号标识。 |
| 知识点 | 带标题、类型、解释与原文页码摘录的模型选择结果。 |
| 来源事实 | 独立理解来源后得到的草稿陈述，继续接受含义审查。 |
| 知识关系 | 由来源命题构建的主语、谓词、宾语及条件，不靠共现推断因果。 |
| 场景 / Scene | 有来源、对象、操作、步骤和核验记录的图示或动画数据。 |
| 系统配音 | Windows 中文系统语音，不标称为 AI 配音。 |
| 确定性演示 | 固定规则生成内容，用于复现工程链路，不标称为 AI 生成。 |

## 2. 平台概述

### 2.1 产品目标

制作教学视频通常需要读取资料、选择知识点、编排讲解、准备图形、配音和剪辑。本项目把这些步骤串成可追踪的流水线，让使用者能检查生成的讲稿和对应资料，再决定如何使用。

当前已实现来源与场景的连接，但尚未实现生成前的知识点编辑与人工审核工作流；不能将课程生成成功理解为已经通过教学审查。

### 2.2 核心功能

| 阶段 | 实际输入 / 输出 |
| --- | --- |
| 上传与存储 | PDF、权利确认、服务配置 → 本机任务编号与原始文件。 |
| 文档解析 | 按文字位置提取；扫描页本机 OCR → 保留物理页码的文字。 |
| 知识与课程 | 来源片段编号 → 知识点、讲解顺序与课程目标。 |
| 图示与脚本 | 定性标题范围检索/复核、独立来源事实 / 命题 → 关系、流程、比较、原页局部放大或可计算几何。 |
| 来源与执行检查 | 引用、逐项含义审查、受限表达式 / 数值关系 → 通过或明确失败。 |
| 媒体制作 | 讲稿与场景 → 配音、逐段动画、完整 MP4、PPTX。 |
| 查看与恢复 | 网页进度、讲稿、来源、关系、下载、失败重试与本地删除。 |

### 2.3 业务流程

准备授权资料 → 选择生成和配音方式 → 上传并确认 → 解析/OCR → 提取知识 → 规划课程与场景 → 核验 → 配音与渲染 → 合成视频与课件 → 用户查看与复核。

当前页面自动推进各阶段，没有中途编辑或人工确认停点。失败任务可调整设置并使用原 PDF 重新生成；符合当前输入和核验规则的缓存可复用。关闭浏览器不会取消任务，停止服务会中断任务。

## 3. 使用说明

### 3.1 环境准备与启动

在仓库根目录使用 Python 3.11+；开发验证使用 Python 3.13。Windows 系统配音需安装中文语音。其他系统可配置兼容的 WAV 语音 API。

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test]"
.\.venv\Scripts\python -m uvicorn zhijiang.main:app --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765/`。在启动服务的终端按 `Ctrl+C` 关闭。可选图示动画安装 `.[math-animation]`；原生关系图与原页讲解不需 TeX，几何和专用数学推演需 `latex` 与 `dvisvgm`。

### 3.2 模式与服务配置

无需模型体验：选“确定性演示模式”和“Windows 中文系统语音”。真实生成：启动本机 Ollama，通过 `ollama list` 确认模型，在页面选择真实 AI 模式并填写本机地址、模型名。也可从 `.env.local.example` 创建 `.env.local`，修改模型后重启；已有文件应直接编辑，避免覆盖配置。

本机地址示例为 `http://127.0.0.1:11434`。配置模板的模型名不意味着已经安装。API 密钥只在任务运行期间保留在服务内存；外部服务需要用户同意发送提取文字或讲稿。网页配置作用于当前任务。

配音可用 Windows 系统语音、本机独立 Kokoro 服务或兼容 `POST /audio/speech` 的 WAV 服务。Ollama 文本服务不是本项目的配音服务。配置和下载步骤见《生成配置与恢复》。

### 3.3 上传与授权

1. 选择有使用权的 PDF，确认文件可正常阅读；上传上限 200 MB。
2. 选择生成模式、动画方式、配音方式，可填写讲解提示词。
3. 勾选资料使用权确认。调用外部服务时还须确认发送提取文本或讲稿。
4. 点击“生成一节课”，保存地址中的任务编号；可用 `/?job=任务编号` 重新打开。

没有授权确认时拒绝创建任务。非 PDF、损坏、空文件、受密码保护等读取问题明确报错，不伪装成成功课程。授权确认是使用者声明，当前不提供许可类别、授权证明上传或自动审定。

### 3.4 任务进度与来源查看

页面显示解析/OCR、知识提取、课程设计、讲稿/分镜、核验、配音、合成、PPT 制作等当前阶段。长文档显示已处理页面/批次；本机模型流式调用显示耗时和已接收字符数。百分比表示阶段进度，不是剩余时间估算。

结果可查看课程目标、逐段讲稿、PDF 页码、原文摘录与场景说明。定性图示可展开“知识关系与来源”。页码采用 PDF 文件物理页码，从 1 起，不一定等于书中印刷页码。

当前没有独立的章节树、知识点勾选、讲稿编辑或公式确认页面。发现错误应回查原 PDF，调整提示词重新上传，或在下载的 PPTX 中人工编辑；网页仅允许失败任务直接重试。

### 3.5 视频、课件与导出

完成任务可在网页播放 MP4，下载 MP4、PPTX；使用通用或专用场景时还可下载场景 JSON。完整视频有配音。PPTX 为每段生成 SVG 摘要页和内嵌动画页，备注含讲稿与来源；通用/专用动画有配音，基础内嵌动画为静音。PPTX 的标题、来源标签和备注可编辑，SVG 不是逐个可编辑的 PowerPoint 形状。

当前不导出独立 SRT/VTT 字幕、审核记录或整套课程 ZIP。结果下载前仍应对照源页面检查概念、条件、公式、画面与口播；没有发布审批或公开分享流程。

### 3.6 失败重试与删除

失败时记录任务编号和错误摘要，在页面修改模型/语音/提示词/动画设置，再点击“使用原 PDF 重新生成”。重试复用符合指纹与当前规则的解析、批次和场景缓存，再配音和渲染；不是任意阶段手动运行。更换外部地址须重新确认发送许可并提供对应密钥。

完成或失败后可点击“删除本地任务与资料”，移除本机任务文件和数据库记录。排队、运行中的任务不能删除。已经下载到其他位置的文件及外部服务留存不在这个删除范围内。

### 3.7 可复现样例

使用仓库 `examples/binary_search_original.pdf`，按以上步骤上传、生成、查看来源和下载。这是原创“二分查找”讲义；参考文档中的数值分析“二分法求根”是另一主题，未将其示意图或期望数值冒充实际生成结果。

历史视频位于 `demo/`，其模型与生成版本见《Demo 操作说明》。四领域真实教材选页的自动规划结果另见《教材泛化验证记录》，它不等同于整书教学合格。

## 4. 边界与异常处理

| 现象 | 处理建议与实际边界 |
| --- | --- |
| 无法上传 / 读取 | 检查扩展名、大小、损坏与密码保护；错误输入不产生成功课程。 |
| OCR 公式或表格错乱 | 对照源页面；现有检查不重建缺失的分母、上下标或表格结构。 |
| 讲解遗漏前提或范围 | 比对标题、引文和口播；来源匹配不代表整章覆盖，当前无必修知识清单。 |
| 模型契约或含义被拒绝 | 查看错误与本机诊断，换模型或调整范围；有限修正失败后保留失败状态。 |
| 语音 / 视频失败 | 确认语音与动画环境，再用原 PDF 重试；媒体生成成功不证明发音和专业内容正确。 |
| 服务中断 | 重启后未完成任务标为失败，再重试；不会自动继续，也没有运行任务取消接口。 |
| 外部服务未同意 | 拒绝发送；地址、模型与密钥由用户配置，本机应用不提供账号体系。 |

## 5. 设计思路与实现方案

### 5.1 原则与分工

来源先于设计；模型负责理解和建议，程序负责数据契约、编号回填、状态、缓存、计算与渲染。模型输出不能作为可执行程序。自动审稿检查当前候选，不是事实正确性的证明；人工审核发布是后续产品能力。

### 5.2 模块化 Agent 工作流

| 业务职责 | 当前实现 |
| --- | --- |
| Document | `pdf.py`：文字位置提取、OCR、物理页码、分页缓存。 |
| Knowledge / Curriculum / Script | `agents.py`、`visual_planning.py`：模型知识提取、排序、讲稿与场景规划。 |
| Visual | `teaching_design.py`、`teaching_graph.py`：来源事实、命题、关系与图示设计；共享布局。 |
| QA | 来源/结构检查、逐项模型含义审查、数值/几何核验及媒体验收脚本。 |
| Media | `speech.py`、`visual_media.py`、`math_media.py`、`video.py`、`presentation.py`。 |
| 编排与存储 | `pipeline.py`、`storage.py`：单机顺序队列、SQLite、失败与缓存恢复。 |

这里的 Agent 是分阶段调用和程序模块，不是六个常驻自治进程。详细字段、接口、状态机与产物路径见《架构与接口》。

### 5.3 知识图谱与动画泛化

来源事实独立于候选画面读取，再提取主语、谓词、宾语和条件。设计模型选择命题编号，程序复制对应关系并核查来源；否定和限定条件保留。箭头表示该谓词，不自动表示因果；比较和原页标注可以没有连线。图的方向、分支和循环决定布局，SVG 与动画共用。

这是一段场景内部的来源知识图，不是整本书的图数据库或完整前置依赖推理。无可信关系时可重新设计为原页注释。来源理解和含义审查仍依赖模型，语言学例句与主题范围的真实缺陷尚未完全解决。

通用数学对象模式 `geometry` 从完整来源页生成受限参数场景，支持函数与参数曲线，静态图和视频用等单位缩放；连续运动与计算结果分别检查。失败不回退为关系图。这个接口没有教材名称分支，但当前小模型和混合页公式输入仍限制效果；四个学段的实际验证见[数学教材报告](math-level-validation-2026-10.md)，不能声称达到完整数学课程或 3Blue1Brown 的制作质量。

### 5.4 数据与恢复

课程数据使用 `SourceDocument`、`Evidence`、`KnowledgeBundle`、`Lesson` 及场景模型。当前任务状态为 `queued`、`running`、`completed`、`failed`，没有 `REVIEW_REQUIRED`。输入哈希与设置指纹控制缓存；旧草稿不是审批，改变关系、条件或讲稿需要重新核查。每阶段独立时间记录、审核版本和细粒度恢复面板属于后续规划。

## 6. 产品价值与创新方向

价值方向是帮助教师与内容制作人员复用合法资料，减少从资料到初版视频的重复操作，并提供可定位的讲稿、场景与来源。当前未进行客户付费、制作时长对照或学习效果实验，不填写未经验证的准确率、节省比例、收入或市场份额。

创新方向包括来源命题约束的图示、多种知识表达共用媒体链路、SVG/配音动画/PPT 来源保持一致、失败后的输入相关缓存。学科不限指规划契约没有学科白名单，不代表任意教材或机制都能正确讲解。

未来可探索机构部署、任务额度或协作服务；需先测量模型、TTS、CPU 渲染、存储与人工审核成本，并核对依赖及教材许可。

## 7. AI Coding 工具使用

实际开发工具为 OpenAI Codex，参与需求、架构、编码、测试、调试与文档整理。开发工具与运行产品的 Ollama/语音模型分开记录。独立《AI Coding 全过程》列出用户需求、真实失败、通用修复、测试和 Git 提交；九月细节保留在归档快照，没有补写未经确认的人员分工或工具版本。

本次整理依据用户确认的文档范围，更新导航、说明、配置参考、实现状态与导出工具，不实现参考原型的工作台或编辑审核流程。第三方组件和模型出处见《第三方来源与许可》。

## 8. Demo 与验收

推荐演示当前实际流程：启动网页 → 上传原创 PDF 并授权 → 观察真实阶段 → 查看课程/来源/关系 → 播放与下载 → 展示失败提示或重试 → 删除已完成任务。参考原型中的知识点编辑与审核操作不在当前 Demo 中。

四领域教材选页已生成 22 张 SVG、22 段配音动画、4 个视频和 4 份课件，媒体检查通过。人工查看仍发现语言学例句误读、标题范围与讲解不完全一致、原页缩略字偏小等问题；教学质量仅部分通过。完整人工听辨与 PowerPoint 放映检查未测试。这批资料参与调试，不是独立盲测。

自动测试与本轮导出结果集中在《验证与验收》；每份历史报告保留其实际输入、版本与结果。不得把媒体解码、模型批准或来源文字匹配混作课程正确性证明。

## 9. 风险与后续规划

优先补足人工修订与知识覆盖：来源核对、知识点选取/排除理由、镜头和必修项映射、脚本编辑、审批与版本失效规则。之后增强复杂公式/表格、独立字幕、任务历史和明确的阶段恢复。机构协作、多语言与个性化课程放在有真实用户验证之后。

路线图使用可验收结果而非未经确认的发布日期；复杂机制、跨章知识图和事实证明不是本次文档整理成果。

## 10. 总结

当前项目具备 PDF 到有来源课程、图示、配音、视频与 PPTX 的本机链路。文档区分实现、技术验收和教学效果，使用者可依据实际来源复核产物。工作台、知识点与讲稿编辑、人工审核发布等参考设计能力继续列为规划。

## 附录 B. 当前 API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/config` | 无密钥的服务配置与动画环境状态。 |
| `POST /api/jobs` | PDF 表单上传、授权与模式设置，成功返回 202。 |
| `GET /api/jobs/{id}` | 查询状态、阶段、进度、错误和产物标志。 |
| `GET /api/jobs/{id}/lesson` | 课程结构、讲稿与来源 JSON。 |
| `GET /api/jobs/{id}/video` | 完整 MP4。 |
| `GET /api/jobs/{id}/presentation` | PPTX 课件。 |
| `GET /api/jobs/{id}/scenes` | 通用或专用场景数据，基础模式可能没有。 |
| `POST /api/jobs/{id}/retry` | 仅失败任务可使用原 PDF 重试。 |
| `DELETE /api/jobs/{id}` | 删除完成或失败任务及本机资料，返回 204。 |

接口参数与状态边界以《架构与接口》和运行中的 `/docs`、`/openapi.json` 为准。参考文档附录的 `project_id`、`review_status` 等示意字段尚未作为当前 API 提供。
